# API Reference (summary)

Interactive documentation: `/api/docs` (Swagger UI, generated by FastAPI).
All responses are JSON. Only APPROVED locations are visible on public endpoints.

## Data model (2026 recreation-location update)
A location row (`Park`) carries: `location_type` (`playground` | `splash_pad` | `beach`),
`name`, `city`, `address`, `lat`, `lng`, `surfacing_material`, `washroom_nearby`,
`water_fountains`, and tri-state facility fields `parking`, `shade`, `fenced`,
`water_access` (accessible water entry; splash pads/beaches), plus `notes`
(description), `review_comment`, five accessibility tri-states +
`accessibility_notes`, `equipment[]` (playgrounds only — required ≥1 for
playgrounds, must be empty otherwise), `photos[]`, and `age_groups_present[]`.
Tri-state booleans are `true` / `false` / `null` (= not assessed).

## Public
- `GET /api/parks` — list approved locations. Filters (combinable):
  `bbox=minLng,minLat,maxLng,maxLat`, `q=<name contains>`,
  `location_type=playground|splash_pad|beach`,
  `equipment_type=`, `age_group=`, `condition=`, `surface=`,
  `accessible=true` (step-free OR inclusive equipment OR accessible surfacing),
  `washroom=true`, `water=true`, `parking=true`, `shade=true`, `fenced=true`,
  `limit=` (≤2000).
- `GET /api/parks/{id}` — one approved location (full record; powers park.html).
- `GET /api/stats` — dashboard aggregates honouring the same filters.
- `GET /api/meta` — vocabularies (`location_types`, `equipment_types`,
  `age_groups`, `conditions`, `surfaces`) + map/geocoder/photo config.
- `POST /api/submissions` — multipart: `payload` (SubmissionIn JSON string) +
  `photos[]`. Rate-limited per IP; honeypot field `website` must be empty.
  Creates a PENDING location; `revision_of_id` marks it as an update to an
  approved one.

## Admin (Bearer token from /api/admin/login)
- `POST /api/admin/login` — `{password}` → `{token}` (HMAC, expiring).
- `GET /api/admin/parks?status=pending|approved|rejected|archived|all`
- `POST /api/admin/parks/{id}/approve` — body `{note?}`. Approving a revision
  archives its predecessor.
- `POST /api/admin/parks/{id}/reject` — body `{note?}`.
- `PUT /api/admin/parks/{id}` — **new (2026)** in-place edit. Body = same shape
  as SubmissionIn (revision/honeypot ignored). Does not change status or create
  a revision; replaces the equipment list; photos untouched.
- `DELETE /api/admin/parks/{id}` — permanent delete incl. photo files on disk.
- `GET /api/admin/export.csv` — flat CSV; one row per equipment item, one row
  total for equipment-less locations. Columns include location_type, address,
  parking/shade/fenced/water_access and all accessibility fields.
